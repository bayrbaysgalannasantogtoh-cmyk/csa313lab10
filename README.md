M2 яагаад амьд үлдэв? Бас яаж унагах вэ?best = present; гээд өөрчилчихсөн байхад яагаад миний тестүүд унасангүй вэ гэхээр, би [1, 1, 1, 1, 1] гэх мэт дандаа хичээлдээ ирсэн тасралтгүй цуваагаар шалгасан учраас тухайн агшинд streak болон present хоёрын утга яг адилхан өсөөд байсан хэрэг. Тэгэхээр програм алдаатай утга оноож байгаагаа анзааралгүй амжилттай ажиллаад байсан гэсэн үг.
Үүнийг барихын тулд би дундаа тасарсан хэрнээ нийт ирц нь их [1, 0, 1, 1, 1, 1] гэсэн тест нэмж mvn-test-M2-kill.txt үүсгэсэн. Ингэхэд жинхэнэ цуваа (streak) нь 4 байтал, нийт ирц (present) нь 5 байсан тул програм хуурамчаар "5-аас дээш цуваатай байна" гэж үзээд илүү оноо өгч алдаа нь баригдсан.

M3-ын талаар:
int total = present + best; гэж нэмэхэд програмын эцсийн үр дүн score-т ямар ч нөлөө үзүүлэхгүй тул тестүүд унахгүй. Харин үүнийг IDE-ийн статик анализын багаж (жишээ нь VS Code) барьж аваад "The value of the local variable total is not used" буюу энэ хувьсагч хаана ч хэрэглэгдэхгүй байна шүү гэж шар зураасаар анхааруулдаг.

Дүгнэлт
Энэхүү лабаас харж байхад DU (Data Flow) анализ нь Branch хамралтаас хавьгүй илүү нарийн, гүн шалгалт хийдэг болох нь харагдлаа. Branch хамралт нь зүгээр л кодын бүх if/else салаагаар орсон эсэхийг л хянадаг бол, DU анализ нь нэг хувьсагчид оноосон утга цаашаа ямар ямар замаар дамжиж хаана очиж хэрэглэгдэж байгаа амьдралын мөчлөгийг тэр чигт нь шалгадаг. Үүний хүчинд M2 шиг логикийн хулгайн алдааг илүү нарийвчилсан тестээр барьж авах боломжтойг ойлголоо.
Гэхдээ үүний сул тал буюу хамгийн их цаг авсан, ядаргаатай хэсэг нь B хэсэг буюу CFG зурж, гараар бүх def-clear замыг хөөж, аль мөрөнд kill хийгдэж байгааг хүснэгтээр гаргах алхам байв. Хүний гараар хийхэд алдаа гаргах магадлал маш өндөр бөгөөд автоматжуулсан багаж зайлшгүй хэрэгтэй санагдлаа.
